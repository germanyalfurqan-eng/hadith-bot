🚀 v1371 — поиск по номеру перестал тянуть сборники целиком

Замер на боевом сайте, настольный браузер и хорошая сеть: поиск по номеру «66» — 78 запросов, 11 мегабайт, 13 секунд. На телефоне это те самые «ужасно долго» и «Загружаю: ibnmaja…», которые владелец показывал скрином.

ПРИЧИНА. Приложение показывает блок «наше издание (стандартная нумерация)» для каждого из восьми канонических сборников — и ради ОДНОЙ записи тянуло каждый сборник ЦЕЛИКОМ: Муслим 2 МБ, Бухари 1,9 МБ, Тирмизи 1,1 МБ, Абу Дауд 1,1 МБ, Насаи 1 МБ, Малик 0,4 МБ. У Муснада Ахмада эту беду вылечили давно — 25 мегабайт не спрячешь; семь книг по мегабайту поодиночке в глаза не бросались, а вместе давали одиннадцать.

ЧТО СТАЛО. Те же файлы нарезаны по 200 номеров. Нужен хадис №66 — приезжает кусок до 350 КБ, а не весь сборник. По расчёту за поиск поедет около 2,3 МБ вместо 43,9 МБ.

Нарезаны ИМЕННО те файлы, по которым приложение уже живёт: нумерация обязана совпасть (у Муслима — Абд аль-Баки, у Дарими — своя печать). Проверено по фактам: 3 400 номеров вразброс по восьми книгам, текст из куска совпал с текстом из полного файла — 0 расхождений. Прежний путь оставлен запасным: куска нет — грузим как раньше, ни один номер не пропадёт.
